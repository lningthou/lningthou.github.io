Part 2 — Fit a Neural Radiance Field from Multi-view Images

Part 2.1 — Create Rays from Cameras

Camera to World Coordinate Conversion

I implemented the transform function to convert points from camera coordinates to world coordinates. The function converts 3D points to homogeneous coordinates by appending ones, multiplies by the c2w matrix, and extracts the resulting 3D world coordinates by removing the homogeneous component.

Pixel to Camera Coordinate Conversion

The pixel_to_camera function converts 2D pixel coordinates (u, v) to 3D camera-space coordinates using the intrinsic matrix K. It extracts the focal lengths (fx, fy) and principal point (ox, oy) from K, then applies the pinhole camera inverse projection formula: x = (u - ox) * s / fx and y = (v - oy) * s / fy, where s is the depth (set to 1.0 for direction rays).

Pixel to Ray

The pixel_to_ray function combines the above transformations to generate rays in world space. Ray origins are extracted directly from the translation component of the c2w matrix (camera centers). Ray directions are computed by first converting pixels to camera coordinates, transforming them to world space, computing the vector from ray origin to the transformed point, and normalizing to unit length.

Part 2.2 — Sampling

Sampling Rays from Images

I created the RaysData class to precompute and store all possible rays from the training images. During initialization, it generates a grid of pixel coordinates (offset by 0.5 for pixel centers) for each image, converts all pixels to rays using the camera parameters, and stores the ray origins, directions, and corresponding RGB values as tensors. The sample_rays method then randomly samples N rays by generating random indices into this precomputed set.

Sampling Points along Rays

The sample_along_rays function implements stratified sampling to generate 3D points along each ray between the near and far bounds. It divides the [near, far] interval into n_samples equal bins of width t_width. For each bin, it samples a point either at the bin center (when perturb=False) or at a random location within the bin (when perturb=True). Finally, it computes the 3D positions using the ray equation: p = o + t * d.

Part 2.3 — Putting the Dataloading All Together

The RaysData class described in Part 2.2 serves as the dataloader for the NeRF training pipeline. It handles converting pixel coordinates to rays and returning ray origins, ray directions, and pixel colors. To verify the correctness of the ray generation and sampling implementation, I visualized the cameras, rays, and samples in 3D using the provided Viser code.

Part 2.4 — Neural Radiance Field

I implemented the NeRF MLP architecture shown below, which takes 3D world coordinates and viewing directions as input and outputs density and RGB color values.

The network uses positional encoding with L=10 for 3D positions (resulting in 63-dimensional input) and L=4 for viewing directions (27-dimensional input). The architecture consists of 8 fully-connected layers with width 256. After the first 4 layers (fc1-fc4), the original position encoding is concatenated with the features via a skip connection before continuing through layers fc5-fc8. The density branch uses a single linear layer with ReLU activation to ensure positive density values. The RGB branch processes features through an additional linear layer, concatenates them with the direction encoding, and passes through two more layers (width 128, then 3) with a final Sigmoid activation to constrain colors to [0,1].

Part 2.5 — Volume Rendering

I implemented volume rendering to convert the density and color predictions along each ray into a final pixel color. The key idea is to accumulate color contributions from points along the ray, weighted by how likely the ray is to terminate at each point. Points closer to the camera contribute more if they have high density, while points further away contribute less if earlier points have already absorbed the light. This is computed by calculating transmittance (how much light reaches each point) and alpha values (probability of the ray stopping at each point), then summing the weighted color contributions.

The volrend function implements this efficiently using cumulative sums to compute transmittance in a vectorized manner. During training, I render batches of rays and optimize using MSE loss between predicted and ground truth colors. The render_image function renders complete validation images by processing all pixels in chunks.

Part 2.6 — Training NeRF on Custom Dataset

I trained NeRF on my own captured dataset of a Rick Sanchez Funko Pop figure. The main challenge was adjusting the near and far bounds to match my scene's depth range, as the object was much closer to the camera compared to the Lego dataset. I also increased the number of training iterations to ensure convergence.

Training hyperparameters for the Rick Sanchez Funko Pop dataset:

Iterations10000
Batch Size10000 rays
Samples per Ray64
Near/Far Bounds0.2 / 0.6
Learning Rate5e-4
Network Width256
Position Encoding (Lx)10
Direction Encoding (Ld)4
Stratified SamplingEnabled with perturbation

Key changes from the Lego dataset: I adjusted the near/far bounds from 2.0/6.0 to 0.2/0.6 to account for the closer camera distance, and increased training iterations from 1000 to 10000 to allow the model more time to learn the details of the Funko Pop.

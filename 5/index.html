Increasing num_inference_steps significantly improved prompt adherence for complex subjects. For the Socrates and Diorama prompts, lower steps 10–20 failed to generate key constraints, rendering a headband or generic 3D terrain instead. Conversely, for the Neon City prompt, higher steps resulted in excessive saturation and sharpness. The lower step count 10 produced a softer, more photorealistic effect.

Part 1.1: Implementing the Forward Process

I implemented the forward(im, t) function which adds noise to a clean image according to the diffusion forward process equation. The amount of noise depends on the timestep t, with higher timesteps adding more noise.

# Forward diffusion: add noise scaled by timestep t
im_noisy = sqrt(alphas_cumprod[t]) * im + sqrt(1 - alphas_cumprod[t]) * noise

Part 1.4: Iterative Denoising

I implemented iterative denoising using strided timesteps (starting from 990, with stride 30, reaching 0). This allows for gradual, step-by-step denoising that produces better results than one-step denoising.

The key idea is to loop through strided timesteps and apply the DDPM update formula at each step:

# Core DDPM update step
x0 = (image - torch.sqrt(1 - alpha_cumprod) * noise_est) / torch.sqrt(alpha_cumprod)
pred_prev_image = term1 + term2 + add_variance(...)

Part 1.6: Classifier-Free Guidance (CFG)

I implemented Classifier-Free Guidance to improve image quality. CFG works by computing both a conditional and unconditional noise estimate, then extrapolating away from the unconditional estimate. I used the prompt "a high quality picture" with a guidance scale of γ = 7.

The key difference from standard denoising is combining conditional and unconditional noise estimates:

# CFG: extrapolate away from unconditional estimate
noise_est = uncond_noise_est + scale * (noise_est - uncond_noise_est)

Part 1.7.2: Inpainting

I implemented inpainting by creating a binary mask and using the diffusion model to fill in the masked region while keeping the rest of the image intact.

The inpaint function is similar to iterative_denoise_cfg, but after each denoising step we blend the result with the original image using the mask. The key difference is:

# After computing pred_prev_image via CFG denoising...
# Blend: keep original outside mask, denoise inside mask
if i < len(timesteps) - 2:
    image = mask * pred_prev_image + (1 - mask) * forward(original_image, prev_t).half().to(device)
else:
    image = mask * pred_prev_image + (1 - mask) * original_image

Part 1.8: Visual Anagrams

I implemented visual anagrams - optical illusions that show different images depending on orientation. I denoise with one prompt, flip the image, denoise with another prompt, flip back, and average the noise estimates.

The make_flip_illusion function extends CFG denoising to use two prompts - one for the upright image and one for the flipped version. The key difference is:

# Flip image, denoise with second prompt, flip back, then average
eps_2 = torch.flip(eps_2_flipped, [2])
noise_est = (eps_1 + eps_2) / 2.0

Part 1.9: Hybrid Images

I created hybrid images by combining the low frequencies from one denoised image with the high frequencies from another. The result shows different images depending on viewing distance.

The make_hybrids function is similar to visual anagrams but instead of flipping, it extracts low frequencies from one prompt's noise estimate and high frequencies from another. The key difference is:

# Combine low frequencies from prompt 1 with high frequencies from prompt 2
eps_low = gaussian_blur(eps_1, ...)
eps_high = eps_2 - gaussian_blur(eps_2, ...)
noise_est = eps_low + eps_high

Analysis

The outputs show blob-like shapes with bright centers - if you squint, you can make out faint curves resembling overlapping digits like 0, 3, 8, and 9. This happens because with MSE loss on pure noise, the model learns to output the centroid of all training images - the single image minimizing squared distance to every digit 0-9. Since the model has no signal to determine which digit to produce, it outputs this "average digit" that captures shared structure but lacks specificity to any particular digit.

Part 2.2: Training the Time-Conditioned UNet

I implemented flow matching with a time-conditioned UNet. During training (Algorithm 1), we sample a clean image x_1, pure noise x_0 ~ N(0, I), and time t ~ U[0, 1]. We interpolate to get x_t = (1-t)x_0 + t*x_1 and train the UNet to predict the velocity field v = x_1 - x_0. The time conditioning is injected via FC layers that modulate features after the bottleneck and first upsampling block.

Part 2.3: Sampling from the Time-Conditioned UNet

To generate images (Algorithm 2), we start with pure noise x_0 ~ N(0, I) and iteratively evolve it toward the data distribution using Euler integration. For each timestep from t = 0 to t = 1, we compute x_t = x_t + (1/T) * v(x_t, t), where v is the predicted velocity from our UNet. After T steps, we arrive at a generated sample.

Part 2.4-2.5: Adding Class-Conditioning to UNet

To generate specific digits, I added class conditioning to the UNet. The class label c is converted to a one-hot vector and passed through FC layers, similar to time conditioning. The class and time embeddings are combined via:

# Class and time conditioning combined multiplicatively and additively
x_unflat = c2 * x_unflat + t2  # at bottleneck
x = c1 * x + t1                 # after first upblock

For classifier-free guidance during training, I randomly drop the class condition with probability p_uncond = 0.1 by zeroing out the one-hot vector using a mask. This teaches the model to generate both conditionally and unconditionally.

Part 2.6: Sampling from the Class-Conditioned UNet

During sampling, I use classifier-free guidance by computing both conditional and unconditional velocity predictions, then extrapolating:

# CFG for class-conditioned sampling
v = v_uncond + guidance_scale * (v_cond - v_uncond)
